## 2026-08-31 — Phase 4 (part 1): SessionStore, AuditLogger, and a real RBAC-bypass fix
**Commit:** `eef9a98` (session store, audit logger, engine wiring) + `6dc4dd8` (the two policy files' `roles` field, committed separately per this repo's `block-ci-policy-edits` hook)
**Changed:** `firewall/session.py` (new — `SessionStore`: append-only, immutable `_SessionRecord` snapshots, one `threading.Lock` per session, TTL eviction with an injectable clock for INV-13); `firewall/logger.py` (new — `AuditLogger`: SHA-256 hash-chained audit rows over WAL-mode SQLite via SQLAlchemy, `redact_value` secret-pattern redaction, context-manager `close()` fixing a real Windows SQLite file-lock bug found during smoke-testing); `firewall/policy_engine.py` (`PolicyEngine` now takes optional `session_store`/`audit_logger`, records every ALLOWed call's history and shadow-logs every decision with latency; closes the "session history always empty" Phase 3 gap for `sequence`/`rate` rules); `requirements.txt` (added explicit `sqlalchemy==2.0.52`, previously only transitive); `tests/test_session.py` (new, 12 tests incl. an 8-thread×200-call concurrency test); `tests/test_policy_engine.py` (new `PolicyEngine`-integration tests for session recording and shadow logging).

Also found, during this integration testing (not by the earlier code review), and fixed a real authorization-bypass bug: `path_scope`/`domain_allowlist` rules were unconditional `action: allow` grants matching any role, so per conflict resolution's "any matching ALLOW is independently sufficient" rule they silently outvoted a co-located `rbac` rule's role restriction on the same tool rather than composing with it — an `intern` (no RBAC grant) could still read any in-scope file via `read_file` and email the corp domain via `send_email`. Fixed by adding an optional `roles` field to both rule types (empty = unrestricted, unchanged default) and setting it on the two affected shipped rules (`path-read-file-sandbox`, `domain-send-email-corp`) to match their sibling `rbac` rule. See ADR `0012-rbac-composition-with-allowlist-rules`.
**Why:** Phase 4 deliverable per the master build prompt — session state and a tamper-evident audit trail. The RBAC-bypass fix was not planned work; it surfaced from real end-to-end testing once `PolicyEngine` started actually recording session history and logging real decisions, which is exactly the kind of gap ad hoc unit tests (each isolating one rule) can't catch.
**Files:** `firewall/session.py`, `firewall/logger.py`, `firewall/policy_engine.py`, `firewall/policy_schema.py`, `policies/path_scope.yaml`, `policies/domain_allowlist.yaml`, `requirements.txt`, `tests/test_session.py`, `tests/test_policy_engine.py`, `docs/knowledge/decisions/0012-rbac-composition-with-allowlist-rules.md`, `docs/knowledge/concepts/policy-engine.md`, `docs/knowledge/index.md`, `LIMITATIONS.md`
