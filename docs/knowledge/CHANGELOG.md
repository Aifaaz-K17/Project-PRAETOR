Also found, during this integration testing (not by the earlier code review), and fixed a real authorization-bypass bug: `path_scope`/`domain_allowlist` rules were unconditional `action: allow` grants matching any role, so per conflict resolution's "any matching ALLOW is independently sufficient" rule they silently outvoted a co-located `rbac` rule's role restriction on the same tool rather than composing with it — an `intern` (no RBAC grant) could still read any in-scope file via `read_file` and email the corp domain via `send_email`. See ADR `0012-rbac-composition-with-allowlist-rules`.
**Why:** Phase 4 deliverable per the master build prompt — session state and a tamper-evident audit trail. The RBAC-bypass fix was not planned work; it surfaced from real end-to-end testing once `PolicyEngine` started actually recording session history and logging real decisions, which is exactly the kind of gap ad hoc unit tests (each isolating one rule) can't catch.
