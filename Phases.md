> Companion to `PROGRESS.md` (status checklist) and `LIMITATIONS.md` (honest
> gaps register). This file exists to **teach** — each phase explains *what*
> was built, *why it was built that way*, *what technology does the work*,

## Before any phase: one-time environment setup

```bash
git clone https://github.com/Aifaaz-K17/Project-PRAETOR.git
cd Project-PRAETOR

python -m venv venv
# Windows PowerShell:
.\venv\Scripts\Activate.ps1
# Linux/macOS:
source venv/bin/activate

pip install -r requirements.txt -r requirements-dev.txt
```

- `requirements.txt` — the library's own runtime dependencies (LangChain,
  Pydantic, PyYAML, FastAPI, Streamlit, idna, ...), each pinned to an exact
  version.
- `requirements-dev.txt` — tooling only needed to *work on* the project
  (ruff, black, mypy, pre-commit, detect-secrets, bandit, pip-audit) —
  never imported by the library itself.
- `requirements.lock` — the full frozen dependency closure (`pip freeze`),
  kept for exact reproducibility; not something you install directly.

Then, once per clone, install the git hooks that run automatically before
every commit (secret scanning, formatting, linting — see Phase 0):

```bash
pre-commit install
```

That needs the `gitleaks` binary on your `PATH` too — see `README.md`
step 4 for the one-time download.

## Phase 0 — Scaffolding, Secret Protection, Threat Model

**Goal:** before a single line of firewall logic exists, make it
*impossible* to accidentally commit a secret, and write down precisely
what the finished project will and will not protect against.

### What was actually done

1. **Repository layout.** Created the directory tree `CLAUDE.md` §1
   specifies: `firewall/` (the library), `policies/` (YAML rules, not
   written yet), `demo_agent/` (mocked LangChain tools), `dashboard/`
   (Streamlit UI, not built yet), `tests/`, `docs/` (including
   `docs/knowledge/` — an Obsidian-style linked notes vault), `scripts/`,
   `sandbox/` (a throwaway fixture filesystem for file-tool tests).

2. **Secrets-first tooling**, so protection exists *before* the thing it
   protects:
   - `.gitignore` / `.gitattributes` — keeps `venv/`, `*.db`, `.env`, and
     OS/editor cruft out of git; normalizes line endings.
   - `.pre-commit-config.yaml` — a chain of checks that run automatically
     on `git commit`:
     - **gitleaks** (`gitleaks-system` hook) — scans the actual diff being
       committed for hardcoded secrets (API keys, tokens, private keys).
     - **detect-secrets** — a second, complementary secret scanner, checked
       against a baseline file (`.secrets.baseline`) so known-safe strings
       (like test fixtures) don't trigger false alarms every time.
     - **ruff** — a fast Python linter (catches unused imports, obvious
       bugs, style issues).
     - **black** — an opinionated Python code formatter (no debates about
       where to put a comma — one canonical style).
     - **mypy** — a static type checker, run only against `firewall/`
       (CLAUDE.md scopes it there deliberately — that's the security-
       critical code).
     - **check-added-large-files** / **end-of-file-fixer** — small hygiene
       checks from the standard `pre-commit-hooks` collection.
     - Two **custom local hooks** written for this project:
       `block-db-files` refuses any commit touching a `*.db`/`*.sqlite`
       file (those are runtime output, never source); 
       `block-noninteractive-policy-edits`
       (`scripts/hooks/block_policy_commits.py`) refuses a commit touching
       `policies/` if it looks like it's running from a script rather than
       a human typing at a terminal (a `sys.stdin.isatty()` check) — a
       defense-in-depth speed bump for INV-03 ("policies are never
       agent-writable"), not the actual enforcement of that invariant
       (which lives in the interceptor's runtime code, not a git hook).
   - `.secrets.baseline` — generated by actually running
     `detect-secrets scan` against the repo (not hand-written), currently
     zero findings.

3. **CI pipeline** (`.github/workflows/ci.yml`) — runs the same checks on
   every push/PR, on GitHub's own servers, so nothing depends on any one
   person's laptop being configured correctly:
   `ruff → black --check → mypy firewall/ → pytest → pip-audit → bandit → gitleaks`.
   Every GitHub Action it uses is pinned to an exact commit SHA (not a
   floating version tag like `@v4`) — the same "no unpinned dependencies"
   discipline `CLAUDE.md` §3 requires of Python packages, applied to CI
   infrastructure too. `permissions: contents: read` at the top of the
   file is the least-privilege default — nothing in this workflow can do
   more than read the repo.

4. **Offline-test enforcement** (`conftest.py`) — a pytest fixture that
   runs automatically before *every single test in the whole suite* and
   makes it impossible for a test to open a real network connection. This
   is INV-14 ("no live targets, ever") enforced mechanically rather than
   trusted to memory. Technical detail worth knowing for the viva: it
   blocks `socket.connect()`/`connect_ex()` to non-loopback addresses —
   *not* socket creation itself, because `asyncio`'s own event loop needs
   a real loopback socket internally on Windows (a bug this project's own
   test suite found and fixed — see `LIMITATIONS.md` Phase 1 section).

5. **Smoke test** (`demo_agent/hello_world.py`) — proves a LangChain
   `@tool`-decorated function can be defined and invoked, *and* proves a
   full "LLM decides to call a tool → tool executes" round trip works with
   **zero API keys and zero network calls**, using LangChain's
   `GenericFakeChatModel` (a chat model that returns pre-scripted messages
   instead of calling a real provider like OpenAI). This is what every
   later phase's "guard the interceptor" work sits on top of.

6. **Threat model** (`docs/THREAT_MODEL.md`) — assets worth protecting,
   the adversary's assumed capabilities (can control any content the agent
   reads; cannot execute code on the host or edit the repo), an
   attack-class-to-control-to-test-evidence table, and — the part most
   projects skip — an explicit **non-goals** section stating what Praetor
   does *not* stop (e.g. a harmful action that's within policy, or
   exfiltration through an allowlisted channel).

### Tech used
Python 3.14.6 · pre-commit · gitleaks · detect-secrets · ruff · black ·
mypy · pytest · pip-audit · bandit · GitHub Actions · LangChain
(`langchain-core`'s `GenericFakeChatModel`, `@tool` decorator)

### How to run / verify this phase

```bash
# The full local CI gate, in the same order ci.yml runs it:
ruff check .
black --check .
mypy firewall/
pytest -v
pip-audit -r requirements.txt
bandit -r firewall/

# The demo, printed to console:

# Confirm the pre-commit hooks are installed and pass:
pre-commit run --all-files
```

**Expect:** all six gate commands exit cleanly with no errors; `pytest -v`

## Phase 1 — Interception Layer (Total Mediation)

**Goal:** intercept *every* tool call an agent makes, before it executes —
with no exceptions, because INV-02 ("total mediation") is, per
`CLAUDE.md` §2, "the single claim the whole project rests on."

### What was actually done

1. **`firewall/context.py` — who is making this call?** Uses Python's
   `contextvars` module (not a global variable, not a function argument) to
   bind a `Principal` (session ID, identity, RBAC role) once, at session
   creation, by trusted server-side code. `contextvars.ContextVar` was
   chosen specifically because it's automatically isolated per thread *and*
   per `asyncio` task — two concurrent sessions can never see each other's
   principal, with no manual locking. This is what makes INV-05 ("a tool
   call cannot set its own role by passing `role="admin"` as an argument")
   possible: the interceptor only ever reads the principal from this
   context, never from the tool call's own arguments, even if a caller
   passes a key literally named `role` or `session_id`.

2. **`firewall/interceptor.py` — the actual enforcement point.**
   - `CallRecord` — a frozen (immutable) snapshot of one call: a unique
     `call_id`, the tool name, the raw arguments, the (Phase 1: identical
     copy, Phase 2 onward: real canonical) arguments, the bound principal,
     timestamps, and a per-session sequence number.
   - `Decision` — `allowed: bool` plus a human-readable `reason`.
   - `Evaluator` — a `typing.Protocol` (structural typing: anything with an
     `evaluate(call) -> Decision` method qualifies, no inheritance
     required). This is the seam Phase 3's real policy engine plugs into;
     Phase 1 only uses small test stand-ins for it.
   - `GuardedToolRegistry.register(tool)` wraps a LangChain tool and
     returns a `GuardedTool`. Every one of its methods —
     `invoke`/`ainvoke`/`run`/`arun`/`batch`/`abatch` — is a thin adapter
     that funnels through one shared internal function, `_evaluate_call`.
     That's the actual mechanism behind "total mediation": there is
     exactly one chokepoint, used by every execution path, so there's only
     one place that could get the security logic wrong instead of six.
   - `_evaluate_call` does three things inside a single `try/except`:
     resolves the principal, builds the `CallRecord`, and calls
     `evaluator.evaluate()`. Any exception anywhere in that block — a
     crashing evaluator, no principal bound, anything — produces a `DENY`
     tagged `FIREWALL_ERROR`, never lets the tool run and never crashes
     the caller (INV-01, "fail closed"). It also takes two independent
     `copy.deepcopy()`s of the arguments *before* calling the evaluator, so
     a careless or hostile policy hook that mutates the arguments it was
     handed cannot change what the tool actually receives (INV-07, no
     "check one thing, then execute a different thing").
   - `firewall_guard(evaluator)` — a decorator offering the same mediation
     for a single plain Python function, for cases where wrapping a whole
     LangChain tool is overkill.

3. **The honest part: a documented, tested residual bypass.** If code
   holds a direct reference to the *original* tool object — the one handed
   to `.register()`, before wrapping — calling that reference skips
   mediation entirely. This is inherent to "wrap at registration": there's
   no way to guard a function you didn't wrap. Rather than hide this, two
   tests prove it happens
   (`test_INV_02_direct_reference_bypasses_registry`,
   `test_firewall_guard_decorator_direct_reference_bypass`), and it's
   written up as risk **R-1** in `docs/THREAT_MODEL.md` with the real
   mitigation: in production, only ever export the guarded object from a
   module, never the raw one.

4. **The headline test**: `test_INV_02_bypass_audit` registers three
   tools, scripts a ten-call session exercising every execution path
   (`invoke`, `run`, `ainvoke`, `arun`, `batch`, `abatch`, two retries),
   and asserts the evaluator was actually called exactly ten times, the
   registry reports nothing unguarded, and every tool an agent would
   receive carries a `__wrapped__` marker (the same convention
   `functools.wraps` uses, meaning "this object wraps something else").

### Tech used
`contextvars` (principal binding) · `typing.Protocol` (structural typing
for the `Evaluator` seam) · `dataclasses` (frozen `CallRecord`/`Decision`)
· `copy.deepcopy` (TOCTOU safety) · `threading.Lock` (thread-safe
per-session call counters) · `asyncio` (async execution paths, tested with
`asyncio.gather` for realistic parallel tool calls) · LangChain's
`BaseTool` (`invoke`/`ainvoke`/`run`/`arun`/`batch`/`abatch`)

# See it work end-to-end in the console (allowed and denied calls):

## Phase 2 — Canonicalization Layer

**Goal:** the policy engine (Phase 3) must never compare a *raw* value
against a rule — INV-06 says every value gets normalized first, because
"parser-differential bypass is the #1 real-world way allowlists fail"
(`CLAUDE.md` §2). This phase was moved *before* the policy engine
specifically so Phase 3 never has to touch raw input at all.

### What was actually done

1. **`firewall/canonicalize.py`** — one `Canonical[T]` result type
   (`original`, `value`, `rejected_reason`, and an `.ok` property) plus
   four functions, one per value shape a mocked tool will need:

   - **`canonical_path(value, allowed_roots, base_dir=None)`.** Uses
     `pathlib.Path.resolve()` — which resolves symlinks and normalizes
     `.`/`..` against the *real filesystem* — and checks containment with
     `Path.is_relative_to()`, never a string comparison. This single
     choice is why a whole family of attacks doesn't apply here at all: a
     sanitizer that strips the literal text `../` once can be bypassed
     with `....//` (stripping one `../` leaves `../` behind); this
     implementation doesn't do string stripping, so that trick has nothing
     to bypass. Similarly, `Path.is_relative_to` correctly rejects a
     sibling directory like `/data-evil` against an allowed root of
     `/data` — a plain `str.startswith("/data")` check would wrongly
     accept it. Also handles single percent-decoding (rejecting if the
     result still looks percent-encoded — that's *double* encoding, e.g.
     `..%252f`, and it's denied rather than decoded again in a loop) and
     rejects NUL bytes, control characters, and Windows UNC paths
     (`\\server\share\...`).
   - **`canonical_host(value)`.** Normalizes a bare hostname to its IDNA
     ("Internationalized Domain Names in Applications") ASCII/punycode
     form — e.g. a Cyrillic look-alike of `apple.com` encodes to a
     *different* string (`xn--pple-43d.com`) than the real one, so it
     simply fails to match an `apple.com` allowlist rule by not being
     equal to it, rather than needing a special "detect homoglyphs"
     check. Rejects anything with an `@`, `:`, `/`, or whitespace in it
     (those indicate userinfo/port-confusion tricks, not a real
     hostname). Paired with `matches_domain_allowlist(host,
     allowed_domain)`, which does *label-boundary* matching — `host ==
     allowed_domain or host.endswith("." + allowed_domain)` — so
     `notevil.com` and `evil.com.attacker.net` can never match a rule for
     `evil.com`.
   - **`canonical_email(value)` / `canonical_email_list(value)`.** Uses
     Python's `email.utils.parseaddr`/`getaddresses` to correctly separate
     a display name from the real address (so `"admin@corp.com"
     <attacker@evil.com>` correctly extracts `attacker@evil.com`), but
     then *rejects the whole value* if the display name itself contains an
     `@` — a strong signal of deliberate spoofing that a human skimming
     only the display name could be fooled by. `canonical_email_list`
     requires every recipient in a comma-separated to/cc/bcc field to pass
     individually; one bad address fails the entire field, so a spoofed
     address can't be smuggled in among legitimate ones.
   - **`canonical_text(value, max_length=4096)`.** NFKC-normalizes
     ("Normalization Form Compatibility Composition" — the standard
     Unicode normalization for comparing visually-equivalent character
     sequences), strips zero-width and bidirectional-formatting
     characters (used to hide characters from a human reviewer, or split a
     denylisted word invisibly), single percent-decodes, and strips
     remaining control characters — which is what defeats embedding a fake
     header via `\r\n` in something like an email subject line. Rejects
     (never silently truncates) anything over the length cap, because
     truncating would mean a malicious payload placed after the cutoff
     never gets checked against any policy pattern at all.

2. **The bypass corpus** (`tests/fixtures/bypass_corpus.yaml`) — 44
   entries, each a small YAML record naming an attack technique, the input
   string, and the expected outcome, parametrized into one test per entry
   by `tests/test_canonicalize.py`. Deliberately excludes anything
   containing a NUL byte, other control character, `\r\n`, or zero-width
   character — those live as plain Python string literals
   (`chr(0x200B)`, `"\x00"`) in the test file instead, because an
   invisible or control character sitting directly in a text fixture file
   is something a reviewer, an editor, or a diff tool could silently
   mangle without anyone noticing. (This same reasoning shaped
   `canonicalize.py`'s own source: its zero-width-character table is built
   from a list of integer Unicode code points via Python's `chr()`
   function, not typed as literal or escaped characters.)

3. **~25 additional dynamic tests** for exactly those excluded cases, plus
   a few that need a value only known at test run time (an absolute path
   into a temp directory; a real symlink) — including a test that
   constructs the *exact* `/data` vs `/data-evil` scenario on disk and
   confirms it's denied.

### Tech used
`pathlib` (`Path.resolve`, `Path.is_relative_to`) · `idna` (third-party
package, IDNA/punycode encoding — newly added as a pinned dependency this
phase) · `unicodedata` (NFKC normalization) · `email.utils` (RFC-aware
address parsing) · `urllib.parse.unquote` (percent-decoding) · `re`
(pattern matching for control characters, residual encoding) · PyYAML
(the bypass corpus file) · pytest's `tmp_path` fixture (real, isolated
temp directories per test, including one used for a real symlink test)

### How to run / verify this phase

```bash
pytest tests/test_canonicalize.py -v
```

**Expect:** 68 passed, 1 skipped. The one skip is
`test_INV_06_path_symlink_to_parent_denied` — creating a symlink on
Windows needs Developer Mode or admin rights, so it skips gracefully

real in CI (`ubuntu-latest`), which is where it matters most.
